# 网格均值聚合栅格设计

## 背景

当前工具已经具备以下基础能力：

- 上传并读取带地理参考的 `GeoTIFF`
- 预览影像、显示分类色带与 hover 信息
- 绘制围栏，并在围栏内生成网格
- 导出围栏、网格和按命中网格写 `NoData` 的 `GeoTIFF`

但当前网格仍然只是空间切分工具，还没有把网格内部的像元值真正聚合成业务结果。用户已经明确新的目标：

- 按网格均值重建一个“聚合栅格视图”
- 地图预览和导出都使用聚合结果
- 围栏外或未命中网格继续写 `NoData`

## 目标

### 业务目标

- 将围栏内每个命中网格内部的有效像元聚合为一个单值
- 以“网格均值”作为当前阶段的默认聚合结果
- 让地图预览、hover 信息和导出结果统一基于同一份聚合数据

### 体验目标

- 用户调整围栏或网格尺寸后，可以实时看到聚合后的格网结果
- 地图所见与导出结果保持一致，减少认知落差
- 后续归一化可以在现有聚合链路上叠加，而不是推翻重来

### 非目标

- 本次不实现复杂归一化公式，只先保留“均值原样输出”
- 本次不处理多波段联合统计，先只使用主波段
- 本次不引入后端计算，仍以纯前端为主
- 本次不增加复杂的分析面板或报表导出

## 方案比较

### 方案 1：只做网格统计，不改地图和导出

优点：

- 实现快
- 对现有链路侵入小

缺点：

- 用户看不到真实聚合结果
- 地图、hover、导出三者不一致

### 方案 2：按网格均值重建聚合栅格视图

优点：

- 地图预览和导出逻辑统一
- 更符合“围栏内网格分析”的直觉工作流
- 后续叠加归一化时边界清晰

缺点：

- 需要新增网格聚合数据结构和计算链路
- 需要同步修改 hover、着色和导出逻辑

### 结论

采用 **方案 2**。

## 聚合规格

### 输入

- 原始上传的 `GeoTIFF`
- 当前围栏几何
- 当前网格尺寸

### 输出

- 每个命中网格的聚合结果
- 聚合结果至少包含：
  - `pixelCount`
  - `validPixelCount`
  - `meanValue`

### 聚合规则

1. 仅对围栏内命中的网格参与统计
2. 仅对主波段参与统计
3. 仅统计有效像元，`NoData` 不参与均值计算
4. 网格均值计算公式：
   - `meanValue = validPixelSum / validPixelCount`
5. 若网格内没有任何有效像元：
   - 该网格聚合值记为无值
   - 地图预览可透明显示
   - 导出时该网格写 `NoData`

## 地图预览设计

### 预览来源

地图预览不再直接沿用原始像元值作为唯一展示依据，而是基于网格聚合结果渲染。

### 渲染效果

- 命中网格保留边界
- 命中网格内部按 `meanValue` 着色
- 无聚合值的网格显示为透明或空白
- 围栏外和未命中网格不显示聚合填充

### Hover 信息

鼠标移入网格时，右侧除现有坐标和网格编号外，新增：

- 网格均值
- 总像元数
- 有效像元数

## 导出设计

### 导出结果

导出的 `GeoTIFF` 继续保持栅格矩形结构，但有效值写法调整为：

- 命中网格内的所有像元统一写成该网格的 `meanValue`
- 未命中网格写 `NoData`
- 围栏外写 `NoData`

### 导出一致性

地图预览和导出必须使用同一份网格聚合结果，避免出现：

- 页面上看的是均值
- 导出出去还是原始像元

这种自找麻烦的割裂行为。

## 数据流设计

### 新增中间层

在现有“围栏 -> 网格 -> 导出”链路之间新增“网格聚合结果”：

- 围栏决定网格范围
- 网格决定像元分桶
- 聚合结果决定预览着色与导出写值

### 计算时机

以下任一条件变化时重算聚合结果：

- 影像重新加载
- 围栏变化
- 网格尺寸变化

### 计算边界

为避免前端无脑扫整图导致卡顿：

- 优先只在围栏包络裁剪窗口内计算
- 通过像元中心所属网格直接分桶
- 避免对每个像元和每个网格做双重几何碰撞判定

## 数据结构建议

建议为每个网格新增聚合字段，或增加单独的聚合结果结构：

- `cellId`
- `pixelCount`
- `validPixelCount`
- `sumValue`
- `meanValue`
- `outputValue`

其中：

- `meanValue` 表示原始聚合均值
- `outputValue` 表示最终用于展示和导出的值

当前阶段先令：

- `outputValue = meanValue`

后续若加入归一化，可只改 `outputValue` 生成逻辑，而不动底层聚合。

## 归一化预留

当前阶段虽然不实现真正归一化，但必须预留入口。

建议后续增加：

- `normalizationMode = 'none' | 'min-max' | ...`

这样后续可以在均值之上继续做：

- 最小最大值归一化
- 百分位拉伸
- 自定义区间映射

而不需要重写整条导出链路。

## 错误处理

需要明确处理以下情况：

- 未上传影像
- 未绘制围栏
- 围栏未命中任何网格
- 网格内无有效像元
- 影像主波段不可读
- 导出过程中写出失败

错误提示应尽量面向用户，不要把底层异常原样乱甩。

## 测试策略

### 纯函数测试

- 单个网格内多像元均值计算正确
- `NoData` 像元被正确跳过
- 无有效像元网格输出为空值
- 命中网格内像元被统一改写为均值
- 未命中网格继续写 `NoData`

### 组件和交互测试

- 修改网格尺寸后聚合结果刷新
- hover 信息显示网格均值和有效像元数
- 地图和右侧信息保持一致
- 导出触发时使用聚合后的结果而非原始像元

## 风险与约束

### 风险 1：前端聚合耗时明显

如果围栏范围大、像元分辨率高，纯前端统计可能导致主线程卡顿。

控制策略：

- 首版先限制只在围栏包络窗口内计算
- 如仍有明显阻塞，再考虑迁移到 `Web Worker`

### 风险 2：预览与导出逻辑分叉

如果预览单独算一套、导出再算一套，后面维护一定变成一锅烂粥。

控制策略：

- 复用同一份聚合结果
- 将“聚合”和“写值”逻辑收敛到共享模块

## 结论

本次采用“**按命中网格统计主波段有效像元均值，并以该均值统一驱动地图预览与 GeoTIFF 导出**”的方案：

- 满足用户对网格单元结果化的核心诉求
- 为后续归一化保留清晰扩展点
- 保持页面预览、hover 和导出结果一致
- 不引入后端，先在当前前端架构内闭环
