# 地理坐标影像米制网格适配设计

## 背景

当前工具已经可以读取带地理参考的 `GeoTIFF`，并支持：

- 影像预览
- 围栏绘制
- 网格生成
- 网格聚合预览
- 导出聚合后的 `GeoTIFF`

但现有实现默认把影像范围和网格尺寸都当成“米制平面”处理，这对投影坐标系影像没问题，对地理坐标系影像就会出错。

典型问题包括：

- 原始范围是经纬度，但面板仍然显示“实际尺寸 xx m x xx m”
- 鼠标坐标只保留两位小数，导致小范围经纬度影像看起来像没有尺寸变化
- 网格尺寸输入的是“米”，但内部直接按“度”去切分范围
- 围栏面积和网格比例对经纬度文件没有真实物理意义

用户已经明确新的目标：

- 网格尺寸继续以“米”为输入单位
- 同时适配投影坐标系和地理坐标系影像
- 对地理坐标系影像显示两套信息：
  - 原始坐标范围
  - 换算后的米制宽高和面积

## 目标

### 业务目标

- 让经纬度 `GeoTIFF` 也能按米制网格尺寸生成合理网格
- 让围栏面积、影像实际尺寸、网格比例在地理坐标系下仍有真实物理意义
- 保持导出结果继续保留原始 CRS 与地理参考

### 体验目标

- 用户无需理解“度”与“米”的换算细节
- 面板上既能看到原始经纬度范围，也能看到换算后的米制尺寸
- 经纬度影像的鼠标坐标、范围和网格显示不再出现“全都四舍五入成一个值”的错觉

### 非目标

- 本次不引入后端坐标服务
- 本次不做全量 CRS 语义解析器，只先覆盖当前 `GeoTIFF` 中可识别的地理坐标系与投影坐标系
- 本次不把整个地图视图强行重投影到新的统一坐标系

## 方案比较

### 方案 1：直接用经纬度差值近似换米

做法：

- 用中心纬度近似估算 `1°lon` 与 `1°lat` 对应米数
- 宽高、面积、网格都基于这个近似关系计算

优点：

- 实现快
- 改动少

缺点：

- 精度一般
- 影像范围稍大时误差会放大
- 网格切分与面积计算都比较粗糙

### 方案 2：建立局部米制平面进行计算

做法：

- 对地理坐标系影像，以影像中心点为基准建立局部米制坐标
- 原始经纬度只负责显示和保留 CRS
- 网格、面积、宽高、比例等所有“物理量”都在局部米制平面中计算

优点：

- 精度和实现复杂度比较平衡
- 用户输入“米”的语义成立
- 不需要改动地图显示的原始 CRS

缺点：

- 需要新增一层坐标转换
- 网格生成逻辑要支持“显示坐标”和“计算坐标”分离

### 方案 3：统一重投影到固定投影坐标系

做法：

- 地理坐标影像先统一重投影，再进行网格计算和显示

优点：

- 理论上计算语义最统一

缺点：

- 工程复杂度高
- 对不同地区和不同源文件不够灵活
- 容易把当前地图显示链路搞得过度复杂

### 结论

采用 **方案 2：建立局部米制平面进行计算**。

## 总体设计

### 核心原则

- 原始影像 CRS 不变
- 地图显示继续使用原始坐标
- 物理尺寸、面积、网格切分统一转入局部米制平面处理

### 双坐标语义

系统中需要明确区分两类坐标：

- 显示坐标：
  - 影像原始 CRS 坐标
  - 用于地图、hover、导出地理参考和原始范围展示
- 计算坐标：
  - 局部米制平面坐标
  - 用于网格尺寸、围栏面积、网格比例、实际尺寸计算

这两类坐标不能再混着用，否则“用户输入米、内部按度切格子”的问题还会继续出现。

## 坐标转换设计

### 投影坐标系影像

若影像 CRS 为投影坐标系：

- 原始坐标直接视作米制计算坐标
- `metricExtent` 直接等于影像原始范围
- 网格尺寸、面积、比例沿用现有逻辑

### 地理坐标系影像

若影像 CRS 为地理坐标系：

- 以影像中心点作为局部坐标换算基准
- 建立“经纬度 <-> 局部米制平面”的双向转换
- 该平面只服务于当前影像的局部计算，不对外暴露为新的正式 CRS

### 转换用途

局部米制转换至少用于：

- 影像实际宽高计算
- 围栏面积计算
- 网格按米切分
- 网格比例计算
- 地理坐标文件下的命中网格判断

### 转换精度要求

- 地理坐标文件只要范围不是跨大区域，局部米制平面精度足够满足当前业务
- 当前目标不是测绘级严丝合缝，而是把“10m 网格”从错误语义修正成真实可用语义

## 数据结构设计

建议在 `RasterMetadata` 或共享几何上下文中补充以下信息：

- `coordinateDisplayMode: 'projected' | 'geographic'`
- `metricExtent`
- `metricWidth`
- `metricHeight`
- `metricTransform`

其中 `metricTransform` 至少应提供：

- `toMetric([x, y]) => [mx, my]`
- `fromMetric([mx, my]) => [x, y]`

要求：

- 对投影坐标系，`toMetric` 和 `fromMetric` 可以退化为恒等变换
- 对地理坐标系，必须提供真实换算逻辑

## 网格生成设计

### 当前问题

当前网格生成直接基于原始 `bbox` 和 `cellSize` 进行切分。

这在投影坐标系下成立，在地理坐标系下会出现：

- 用户输入 `10m`
- 实际却按 `10°` 去切格子

这显然离谱。

### 新设计

网格生成改为两阶段：

1. 在米制计算平面中生成规则网格
2. 将网格四角坐标反算回原始 CRS，生成地图展示 polygon

### 网格命中判断

对于地理坐标系文件：

- 网格中心点、像元中心点、围栏命中判断统一在米制平面中完成
- 避免一部分逻辑在经纬度里跑，另一部分逻辑在米制里跑，最后互相打架

## 围栏与面积设计

### 面积计算

围栏面积显示改为：

- 投影坐标系：直接基于原始坐标计算平方米
- 地理坐标系：先转米制平面，再计算平方米

### 围栏范围展示

围栏范围面板保持显示原始 CRS 范围：

- 若是经纬度，显示经纬度 bbox
- 若是投影坐标，显示投影坐标 bbox

## 面板展示设计

### 左右面板统一展示两类信息

对于地理坐标系影像，面板应同时显示：

- 原始范围：
  - 例如 `119.420000, 36.510000, ...`
- 换算尺寸：
  - 例如 `83.2m x 46.7m`
- 围栏面积：
  - 例如 `1320.5 m²`

对于投影坐标系影像，则沿用现有米制风格即可。

### 坐标显示精度

建议：

- 投影坐标：
  - 范围和 hover 保留 `2~3` 位小数
- 地理坐标：
  - 范围和 hover 保留 `6` 位小数

这样可以避免小范围 GPS 影像被错误地显示成：

- `119.42, 36.51, 119.42, 36.51`

这种看起来像没有范围变化的假象。

### 网格比例

网格比例应始终基于米制宽高计算，而不是原始经纬度差值。

## 地图与 hover 设计

### 地图显示

- 地图仍用原始 CRS 显示影像、围栏和网格 polygon
- 不强行把地图视图整体重投影到新的内部坐标系

### Hover 信息

hover 中：

- 坐标仍显示原始 CRS 坐标
- 地理坐标文件显示更多小数位
- 像元值、网格均值和有效像元数逻辑不变

## 导出设计

### CRS 保持

导出的 `GeoTIFF` 继续保留原始影像 CRS 与 GeoTIFF tag。

### 网格命中逻辑

导出时：

- 投影坐标文件继续走现有米制网格逻辑
- 地理坐标文件改为基于局部米制平面进行网格命中与聚合判断

要求：

- 用户输入的网格尺寸始终按米解释
- 导出的地理参考仍写回原始 CRS

## 错误处理

需要明确处理以下情况：

- CRS 无法识别
- 地理坐标文件缺少足够的空间参考信息
- 局部米制转换初始化失败
- 影像范围异常，无法建立有效物理尺寸
- 用户输入网格尺寸非法

若无法建立米制换算，应明确提示用户当前文件无法进行按米网格计算，而不是偷偷退回按“度”处理。

## 测试策略

### 元数据测试

- 投影坐标文件：
  - `metricExtent` 与原始范围一致
- 地理坐标文件：
  - `metricWidth`、`metricHeight` 为合理米值
  - `coordinateDisplayMode` 为 `geographic`

### 面板展示测试

- 地理坐标文件显示：
  - 原始范围
  - 米制尺寸
  - 正确的坐标精度
- 投影坐标文件回归不退化

### 网格测试

- 地理坐标文件输入米制网格尺寸后：
  - 网格总数合理
  - 命中网格数合理
  - 不再出现按“度”切格的异常结果

### 回归测试

- 当前投影坐标影像工作流保持可用：
  - 读取
  - 预览
  - 网格聚合
  - 导出

## 风险与约束

### 风险

- 若局部米制转换与地图显示坐标混用，容易导致网格边界和命中判断错位
- 若只修文案不修计算层，用户仍会得到错误网格结果
- 若精度处理不统一，GPS 文件仍可能被误判为“没有尺寸”

### 约束

- 当前前端方案仍应保持纯前端运行
- 不能要求用户手动输入坐标单位或自行换算度与米
- 必须兼容现有投影坐标文件链路

## 结论

本次应在现有系统中正式引入“原始 CRS 显示 + 局部米制计算”的双坐标模型。

这样可以同时满足：

- 网格尺寸继续以米输入
- 经纬度文件具备真实物理尺寸和面积语义
- 地图与导出仍保留原始地理参考

这比继续拿经纬度差值硬充米制靠谱得多，也比整套地图重投影更稳妥。
