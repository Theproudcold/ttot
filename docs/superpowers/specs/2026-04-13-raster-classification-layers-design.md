# Raster 分类图层与 NDVI 色带设计

## 背景

当前工具已经支持：

- 本地上传 `GeoTIFF`
- 单波段栅格预览
- 围栏与网格预览
- 基于单一分级规则的灰阶着色
- 右下角图例与 hover 分级信息

现阶段在值渲染层面有三个明显短板：

1. 默认黑白分级不符合植被指数类影像的阅读习惯
2. 当前图例按离散项逐行展示，比较占地图空间
3. 只有一套当前分级规则，无法沉淀多套业务方案并切换使用

用户已经明确要求：

- 默认颜色改为更像植被指数的彩色方案
- 图例压缩为更紧凑的渐变色条样式
- 支持添加多个命名的自定义分类图层/方案
- 允许按业务规则定义分段，例如 `0-0.5`、`0.5-0.7`、`0.7+`

## 目标

### 业务目标

- 为单波段栅格提供更接近 NDVI 阅读习惯的默认彩色渲染
- 允许用户维护多套命名分类方案并在地图上切换
- 支持离散分段着色与连续渐变着色两类图例

### 体验目标

- 地图默认图例更紧凑，不再大块占用视图角落
- 分类方案的增删改查路径清晰，能实时预览结果
- hover 信息能明确告诉用户“当前值命中了哪一套方案里的哪一段”

### 非目标

- 暂不支持多个分类方案同时叠加混合显示
- 暂不支持分类方案导出为带样式的 `tif`
- 暂不实现完整 GIS 图层树、透明度、混合模式、分组管理
- 暂不把 hover 升级为原始满分辨率像元探针，仍基于预览采样值

## 方案比较

### 方案 1：单一当前渲染方案

只保留一套当前分级配置，允许在 NDVI 预设和自定义分段之间切换。

优点：

- 结构最简单
- 对现有状态和 UI 侵入最小
- 实现成本低

缺点：

- 无法保存多套业务方案
- 用户每次调整都要重配
- 不符合用户明确提出的“允许添加自定义分类图层”诉求

### 方案 2：多个命名分类方案

把值渲染提升为一组“分类方案”，每套方案有自己的名称、可见性、渲染规则和图例类型。

优点：

- 符合用户当前目标
- 能沉淀 `NDVI 默认`、`农田重点`、`风险分级` 等多套方案
- 后续扩展导出、复制方案、模板方案都更顺手

缺点：

- 状态管理和 UI 明显更复杂
- 需要额外处理“当前编辑方案”和“当前显示方案”

### 结论

采用 **方案 2**。

为了控制复杂度，本次只支持：

- 多个命名分类方案
- 单次只显示一个“当前可见方案”的图例
- 方案切换后即时重绘

不做多方案叠加混绘。

## 信息架构

### 分类方案

新增一个独立的“分类方案集合”，每个方案至少包含：

- `id`
- `name`
- `visible`
- `mode`
  - `gradient`
  - `discrete`
- `preset`
  - `ndvi`
  - `custom`
- `min`
- `max`
- `rules`
- `legendStops`

其中：

- `gradient` 用于连续色带
- `discrete` 用于离散分段
- `rules` 用于自定义分段规则
- `legendStops` 用于连续色带的颜色停靠点

### 当前活动状态

界面层需要明确两种状态：

- `activeLayerId`
  - 当前正在编辑的分类方案
- `visibleLayerId`
  - 当前正在地图上显示和参与 hover 命中的分类方案

本次为了避免混乱，默认这两个 id 保持一致。后续如果需要做“编辑 A、显示 B”，再解耦。

## 默认方案

系统初始内置一套 `NDVI 默认` 分类方案。

### 默认行为

- 名称：`NDVI 默认`
- 类型：`gradient`
- 预设：`ndvi`
- 默认可见：`true`
- 默认作为当前活动方案

### 默认颜色方向

颜色不再使用黑白灰，而采用更接近植被指数阅读习惯的连续色带：

- 低值：棕灰/土色
- 中低值：浅黄
- 中值：黄绿
- 中高值：亮绿
- 高值：深绿

这个色带的目标不是“遥感专业出版级别”的绝对标准，而是让前端预览一眼能看出“植被越强越绿”的趋势。

## 图例设计

### 渐变图例

对于 `gradient` 方案：

- 地图右下角显示一条横向或竖向紧凑色带
- 色带两端显示最小值和最大值
- 中间可显示少量刻度，不显示逐项离散列表

示意：

- `[棕 -> 黄 -> 绿]`
- 左侧 `-0.4`
- 右侧 `1.0`

### 离散图例

对于 `discrete` 方案：

- 图例仍使用分段列表
- 但列表样式更紧凑
- 每段显示颜色块 + 区间标签

### 图例显示规则

- 地图上只显示当前可见方案的图例
- 如果没有可见方案，则不显示图例
- 如果当前方案被切到不可见，则自动选择下一套可见方案作为图例来源

## 左侧面板交互

左侧“值渲染”区域重构为两部分：

### 1. 分类方案列表

每套方案显示：

- 名称
- 类型标签
- 可见开关
- 是否当前编辑中

支持操作：

- 新建方案
- 复制方案
- 重命名
- 删除方案
- 设为当前

### 2. 当前方案编辑器

根据当前方案类型显示不同编辑表单。

#### 渐变方案编辑器

字段：

- 名称
- 最小值
- 最大值
- 渐变停靠点颜色

允许用户在 NDVI 预设基础上微调范围，但默认直接可用。

#### 离散方案编辑器

字段：

- 名称
- 多行分段规则

每行规则包含：

- `min`
- `max`
- `color`
- `label`

其中：

- 最后一段允许 `max` 为空，表示“以上”
- `label` 允许自动生成，也允许用户自定义

示例：

- `0 ~ 0.5` 灰色
- `0.5 ~ 0.7` 黄色
- `0.7+` 绿色

## 地图渲染设计

### 渲染输入

继续复用当前 `preview.sampleData` 和 `preview.sampleRanges`。

优点：

- 不改 GeoTIFF 读取主链
- 切换方案时无需重新读取文件
- 满足当前“实时预览”的核心目标

### 渲染流程

1. 读取当前可见方案
2. 根据方案类型生成颜色映射器
3. 把 `sampleData` 映射为新的 RGBA
4. 生成新的预览图 `data url`
5. 更新地图静态影像层

### 方案类型对应行为

#### `gradient`

- 连续值按线性插值映射到色带
- `min/max` 外的值按端点钳制

#### `discrete`

- 按规则顺序命中第一个符合区间的分段
- 不命中则透明或回落到默认颜色
- `NoData` 继续保持透明

## Hover 设计

hover 信息追加以下字段：

- 当前显示方案名
- 当前命中区间/标签
- 当前命中颜色

展示顺序建议为：

- 坐标
- 像元位置
- 像元值
- 分类方案
- 分级区间
- 分级颜色
- 围栏命中
- 网格命中

如果当前没有可见方案，则：

- 分类方案显示 `--`
- 分级区间显示 `--`
- 分级颜色显示 `--`

## 数据结构设计

建议新增以下类型：

- `RasterClassificationLayer`
- `RasterClassificationMode`
- `RasterGradientStop`
- `RasterClassificationRule`
- `RasterLayerMatchResult`

其中：

- `RasterClassificationRule` 表示离散规则
- `RasterGradientStop` 表示渐变停靠点
- `RasterLayerMatchResult` 表示 hover 命中后的结构化结果

`mapUiStore` 从当前的单一 `rasterRenderSettings` 升级为：

- `classificationLayers`
- `activeClassificationLayerId`
- `visibleClassificationLayerId`

并提供：

- `addClassificationLayer`
- `updateClassificationLayer`
- `deleteClassificationLayer`
- `duplicateClassificationLayer`
- `setActiveClassificationLayer`
- `setVisibleClassificationLayer`
- `toggleClassificationLayerVisibility`

## 校验规则

### 渐变方案

- `min < max`
- 至少存在两个渐变停靠点
- 停靠点位置必须在 `0 ~ 1` 范围内

### 离散方案

- 至少一条规则
- 每条规则必须有颜色
- `min/max` 必须满足区间顺序
- 相邻规则不允许出现明显倒挂
- 最后一条允许 `max` 为空

如果配置不合法：

- 面板给出明确提示
- 地图保持上一次合法渲染结果

## 风险与限制

### 风险 1：状态膨胀

如果把“图层”概念做得太真，当前项目的轻量结构会迅速复杂化。

控制方式：

- 本次只做分类方案，不做通用图层树
- 地图上同时只展示一个当前方案的图例

### 风险 2：渲染频繁重建

每次切换方案都会重新生成预览图 `data url`，大图下会增加主线程压力。

控制方式：

- 仍基于降采样预览，而不是原始满分辨率像元
- 仅在当前可见方案变化时重建

### 风险 3：用户误以为是原始精确值分析

当前 hover 与着色都基于预览采样值，不是逐像元精确探针。

控制方式：

- 在文案和后续说明里明确这一点

## 最终结论

本次采用“**多个命名分类方案 + NDVI 默认渐变 + 自定义离散分段**”的设计：

- 默认提供符合植被指数认知的彩色渐变
- 图例改为紧凑色条，减少地图遮挡
- 支持创建多套业务分级方案并实时切换
- 保持当前纯前端预览架构，不引入后端或原始像元级重采样

这版能满足当前用户对“更像 NDVI、更省地方、可维护多套自定义分段规则”的核心诉求，同时把复杂度控制在现有项目可承受范围内。
