# GeoTIFF 分阶段加载与网格预览优化设计

## 背景

当前前端工具已经具备以下基础能力：

- 选择本地 `tif/tiff` 文件并读取 `GeoTIFF`
- 使用 `OpenLayers + GeoTIFFSource` 显示影像
- 绘制/编辑围栏
- 基于围栏生成网格预览并导出 `GeoJSON`

现阶段的主要体验问题有三类：

1. 首屏读取容易表现为“卡住不动”
2. 元信息展示过晚，用户看不到文件是否被正确识别
3. 网格预览容易因为范围过大或网格过密导致卡顿，且当前视角下不容易看清

本设计的目标不是扩展产品边界，而是在纯前端架构下把读图、预览和交互体验拉回可用状态。

## 目标

### 业务目标

- 用户上传本地 `GeoTIFF` 后，尽快看到影像和关键元信息
- 围栏绘制在有效区域约束下保持可交互
- 网格预览在不同缩放下都能给出可理解的反馈

### 体验目标

- 不再出现长时间停留在 `0%` 且界面无变化的假死感
- 元信息尽早显示，不依赖整套后处理完成
- 网格显示要说明“总量”和“当前预览量”的区别

### 非目标

- 暂不引入后端切片服务
- 暂不实现遥感分析、归一化算法和多源融合
- 暂不实现完整多图层管理系统，只为现有底图/围栏/网格提供可理解的显示控制

## 现状与根因

### 读取卡顿

当前实现里，文件读取、元信息解析和有效区域提取之间耦合过紧。用户在首屏阶段看不到“哪些工作已经完成”，即使影像具备足够的信息可以先展示，也会被后续重计算拖慢体感。

### 元信息展示延后

文件名、CRS、像元大小、影像尺寸、实际范围等信息都来自 `GeoTIFF` 元信息，本质上可以早于有效区域和网格预览得到。但当前交互没有把这些信息作为优先展示阶段单独处理。

### 网格预览成本过高

网格预览逻辑会根据围栏 bbox 和网格尺寸推算总格数。如果用户设置较小网格尺寸，会快速进入高数量级场景。在这种情况下，地图上一次性生成和渲染大量格线毫无必要，也会直接拖垮主线程。

## 方案概述

采用“分阶段加载 + 后台补计算 + 视野内预览”的策略：

1. 上传文件后优先读取并展示元信息
2. 元信息就绪后立即显示影像
3. 有效区域掩膜放到单独后台阶段处理
4. 网格只显示当前可预览部分，不再追求一次性展示全量

## 详细设计

### 1. 分阶段加载链路

文件上传后的处理拆为以下阶段：

1. `正在读取文件`
2. `正在解析元信息`
3. `影像预览已就绪`
4. `正在准备有效区域`
5. `有效区域已就绪`

#### 阶段行为

- `正在读取文件`
  - 负责本地文件读取和进度更新
  - 进度一旦开始推进，不允许停留在 `0%`

- `正在解析元信息`
  - 解析 `GeoTIFF` 的宽高、bbox、resolution、CRS 等信息
  - 一旦成功，左侧面板立刻显示文件基础信息

- `影像预览已就绪`
  - 地图立即加载影像图层
  - 不等待有效区域掩膜完成

- `正在准备有效区域`
  - 后台抽样或读取 `nodata` 掩膜
  - 不阻塞影像显示

- `有效区域已就绪`
  - 围栏限制从 bbox 约束升级为真实有效区域约束

### 2. 元信息优先展示

元信息面板需要优先显示以下字段：

- 文件名
- 地理参考状态
- 像素尺寸
- CRS
- 像元大小
- 影像实际尺寸（米）
- 有效区域状态

#### 实际尺寸计算

对于投影坐标系影像，直接使用 `boundingBox` 计算：

- 宽度 = `maxX - minX`
- 高度 = `maxY - minY`

如果 CRS 为米制投影，则结果直接以米显示。

### 3. 围栏限制策略

围栏限制采用两阶段校验：

#### 阶段一：仅 bbox 限制

在有效区域掩膜未完成前：

- 围栏必须落在影像 `boundingBox` 内
- 允许先进行基础绘制和编辑

#### 阶段二：有效区域限制

当有效区域掩膜准备完成后：

- 围栏的边界采样点必须全部落在有效像元区域
- 围栏内部落入的掩膜格必须为有效值
- 非法围栏直接拒绝，并给出明确提示

提示文案示例：

- `围栏必须落在影像范围内。`
- `围栏必须落在影像有效数据范围内。`

### 4. 网格预览策略

网格逻辑拆分为“总量计算”和“显示预览”两个层次。

#### 总量计算

无论地图当前显示多少，右侧面板都应保留以下统计：

- 当前网格尺寸
- 预计总网格数
- 当前实际预览格数
- 是否处于降级预览状态
- 当前抽样步长

#### 显示预览

地图上的网格不再追求“全量永远显示”，而改为：

- 只渲染当前可承受数量的预览格
- 超阈值时按抽样步长降级
- 后续进一步优化为仅渲染视野内格线

告警文案示例：

- `网格过密，当前按 4x4 抽样预览。`
- `当前仅显示视野内网格预览。`

### 5. 默认网格尺寸

默认网格尺寸统一调整为 `10m`。

行为规则：

- 应用初始加载时输入框默认显示 `10`
- 用户上传新 tif 后，网格尺寸重置为 `10`
- 不继承上一张影像的残留尺寸配置

这样可以避免用户在极小默认网格下直接进入高密度预览，提升首屏可理解性。

### 6. 网格比例展示

右侧结果面板增加网格比例信息，帮助用户理解“当前网格相对影像有多大”。

建议展示：

- `影像实际尺寸：83.01m x 46.73m`
- `当前网格尺寸：10m`
- `网格占影像宽度比例：12.0%`
- `网格占影像高度比例：21.4%`

如果尚未上传影像，则仅显示当前默认网格尺寸，不展示比例。

### 7. 缩放与视图控制

当前地图视图应优先依赖 `GeoTIFFSource.getView()` 提供的原生视图配置，避免手动覆盖导致放缩表现异常。

后续补充两个操作入口：

- `适配影像`
- `适配围栏`

目标是避免用户“其实网格已经生成，但镜头没对准”的迷惑场景。

## 数据流调整

### Raster Store

新增或明确以下状态：

- `status`
- `loadingPhase`
- `loadingProgress`
- `metadata`
- `validityMask`
- `validityStatus`

### Fence Store

新增：

- `validationMessage`

用于承载围栏超范围、超有效区的明确错误提示。

### Grid Store

`summary` 中保留：

- `totalCells`
- `previewCellCount`
- `isPreviewLimited`
- `previewStride`
- `warning`

## 错误处理

错误提示必须面向用户，不允许只有技术细节。

推荐错误文案：

- `文件读取失败，请重新选择 TIFF 文件。`
- `GeoTIFF 元信息解析失败。`
- `当前网格过密，仅显示局部预览。`
- `围栏超出影像有效区域。`

## 测试策略

### 单元测试

- 元信息读取与尺寸计算
- 进度百分比不再卡在 `0%`
- 有效区域掩膜判断
- 网格降级摘要

### 组件测试

- 左侧面板在元信息就绪后立即显示尺寸/CRS/像元大小
- 顶部状态栏显示阶段式读取状态
- 右侧结果面板显示总网格数、预览网格数与告警

### 集成验证

- 上传 `test2.tif` 后，先看到元信息，再看到影像
- 有效区域未就绪时可进行 bbox 级围栏限制
- 有效区域就绪后启用严格约束

## 实施顺序

1. 将默认网格尺寸改为 `10m`
2. 拆分元信息加载与有效区域提取
3. 优先展示元信息与影像
4. 完善阶段式状态与错误文案
5. 优化网格预览摘要与比例展示
6. 补充视图适配入口

## 风险与后续

### 当前风险

- 有效区域掩膜仍在前端计算，超大影像时仍可能有后台处理延迟
- 视野内网格裁剪若未进一步实现，仍可能在极端围栏下带来额外渲染压力

### 后续建议

- 将有效区域提取迁移到 `Web Worker`
- 将网格显示进一步升级为视野级增量渲染
- 视情况引入更轻量的多层显示控制，但不扩大为完整 GIS 图层系统
